React 和 JSX

jsx 是 JavaScript XML 的简写，在 JavaScript 文件中写 HTML-like 标签

  • 因为jsx不是标准的ECMAScript语法，而是它的语法扩展，所以在普通环境是不可以使用的；要在脚手架中使用（因为脚手架中包含了babel，@babel/preset-react）

JSX 和 React 是两个东西，前者是语法拓展，后者是一个 JavaScript 库。React 是使用了这种语法拓展。通常是一起使用的，但也可以分开使用。更多介绍

React 中 state 中数组的操作方法推荐（避免使用改变数组的，推荐使用返回新数组的）：

避免 推荐
添加 push, unshift concat, […arr]
删除 pop, shift, splice filter, slice
替换 splice, arr[i]=xx map
排序 reverse, sort 先复制这个数组

添加内容：和对象一样，使用扩展运算符来复制以达到改变某一个值的目的

  • 要改变新插入值的位置，将新插入的值这行放到扩展运算的上面就行

删除内容：最简单的就是过滤掉这个不需要的，或者直接创建个新数组的不包含这个要删除的内容

替换内容：在原有的基础上创建一个新的数组，使用map，如果符合，改变这个值然后返回，不符合的返回原来的样子

插入内容：确定要添加的位置，然后使用slice分割数组，将要添加的放到两个切片中间

其他操作：比如 反转，排序，js 方法会改变旧的数组，所以要先复制出一个数组然后再做出改变，如nextList.sort()，nextList[0] = {name: "zs", age: 18}

对于数组 list 和 nextList，虽然不是相同的数组，但是list[0]和nextList[0]指向的是相同的对象，所以直接nextList[0].age=19这样的还是不推荐的，因为这是浅拷贝，是直接改掉了对象里面的东西

👉 更新数组里面的对象

对象其实并不是再数组里面的，只是在代码这里看起来是在里面；但事实上当使用数组时（虽然已经使用拓展运算符复制出不同的数组），尝试改变其中数组内元素的值，另外的引用也会跟着改变，因为数组它内容本身还是和旧数组一样，只是在新的数组里面呆着罢了

render props（遗留模式）

现代 React 中，状态复用已由自定义 Hooks 取代，render props 模式仅在维护旧项目时需要了解。

核心思想：组件接收一个函数 prop（通常叫 render 或用 children），组件内部调用该函数并传入自身状态，函数返回值作为渲染内容。

组件之间的通讯

父组件传给子组件

  • 父组件提供要传递的state数据
  • 子组件标签添加属性，值为state中的数据
  • 子组件通过props接收父组件中传递的数据

子组件传给父组件

  • 父组件提供回调函数，用来接收数据（谁要接收数据，谁就提供回调函数）
  • 将改函数作为属性的值，传递给子组件

兄弟组件传值

  • 将要共享的数据提升到最近的公共度组件中
  • 公共父组件要做的事：提供共享数据、提供操作共享数据的方法
  • 要传值的子组件通过props接收数据或是接收操作数据的方法

setState 说明（遗留模式）

类组件的 setState 是异步批量更新的：

  • 多次 setState 合并为一次 render
  • 推荐使用函数式更新：setState((state, props) => { return { count: state.count + 1 } })，避免拿到旧值
  • 第二个参数为回调，在状态更新且界面重新渲染后执行

函数组件中 useState 的更新同样异步，使用函数式更新 setCount(prev => prev + 1) 解决连续调用问题。

虚拟 DOM 和 Diff 算法

  • 虚拟 DOM 本质上是 JavaScript 对象，用来描述希望看到的内容（即 JSX 对象）
  • 执行过程：初始渲染创建虚拟 DOM 树 → 生成真实 DOM → 数据变化后创建新虚拟 DOM → Diff 算法对比 → 只更新变化的部分
  • render 调用不等于浏览器更新，仅表示要进行 Diff

虚拟 DOM 不是真正的 DOM，只要能运行 JavaScript 的地方就可以使用，这使得 React 可以脱离浏览器运行（React Native）

useEffectEvent

📦 React 19

在 Effect 里能安全地使用最新的 props 和 state，同时又不必把这些频繁变化的值放进依赖数组里。

场景

  • 不加 theme，主题切换时on回调里面的theme还是旧的值
  • 加上 theme，Effect 会重新执行导致connection断开重连

解决方式：

原理是使用了类似“代理模式”的机制：

  1. 返回的onConnected是一个稳定、不变的引用。意味着把它放在 Effect 的依赖数组中不会导致 Effect 重运行
  2. 内部保持更新：React 背后维护一个.current属性，指向传给useEffectEvent的最新函数逻辑，当调用onConnected时，React 调用.current指向的最新函数，从而确保能访问到最新的theme

常见使用场景：

  • 订阅和事件监听：WebSocket、EventEmitter 或者 DOM 事件回调函数需要访问状态，但是又不能因为状态变化而重新订阅（比如出发了重新渲染）
  • 定时器需要读取最新值，但是 Effect 又不能因为这个值的变化触发 Effect 而重新计算

使用限制：

  • 尽在 Effect 中调用
  • 如果 Effect 本身需要这个依赖才能触发，那不应该在useEffectEvent中使用

Profiler

用于测量 React 组件渲染的性能开销。它需要两个属性：id（字符串）和 onRender 回调（子组件树更新时会被调用）。

用途：开发环境识别渲染瓶颈，分析哪些组件重新渲染慢。

回调参数：id, phase, actualDuration, baseDuration, startTime, commitTime

  • id：<Profiler>树的 id 属性，如果使用了多个 profiler，可以通过此属性区分
  • phase：有 “mount”、”update”、”nested-update”，了解组件是首次挂载还是由于 props、state、hook 触发的重新渲染
  • actualDuration：此次更新的渲染耗时，这个时间可能是优化之后的（使用了memo、useMemo记忆）
  • baseDuration：估算没有任何优化情况下的渲染耗时，然后与 actualDuration 对比

此组件生产环境默认禁用

StrictMode

检测不安全的生命周期、意外的副作用（如组件内重复调用渲染或 constructor）、过时的 API

用途：通常包裹整个应用（或其一部分）

  • 组件额外渲染一次以查找由于非纯渲染而引起的错误
  • 组件重新执行一次Effect以查找由于缺少 Effect 清理而引起的错误
  • 组件额外执行一次 refs 回调以查找缺少ref清理函数引起的错误

Error Boundaries

📦 React 16+

用于捕获子组件树中的 JavaScript 错误，展示降级 UI，防止整个应用白屏崩溃。

Error Boundary 必须是类组件（函数组件无法实现），这是类组件仍有价值的少数场景之一。

Error Boundary 不捕获：事件处理函数错误、异步代码错误、setTimeout/requestAnimationFrame 回调错误。这些需要用 try/catch 或 window.onerror 处理。

Server Components

📦 React 18（实验性）/ React 19（稳定）

Server Components（RSC）是在服务端执行的组件，不会发送到客户端，也不占用客户端 bundle 体积。

维度 Server Component Client Component
运行环境 服务端 客户端（浏览器）
能否使用 useState/useEffect ❌ ✅
能否直接访问数据库/文件系统 ✅ ❌
能否使用事件监听（onClick 等） ❌ ✅
Bundle 体积影响 不计入客户端 bundle 计入客户端 bundle
文件后缀约定 .server.tsx 或默认 .client.tsx（使用 "use client" 指令）

实践建议：默认用 Server Component，只在需要交互（状态、事件、浏览器 API）时才标记为 Client Component。这是 Next.js App Router 的默认模式。
