生成的结构：

Controller：只负责解析请求

Controller 的职责边界很窄：从 HTTP 里取参数、调用 Service、返回结果。不要在这里写业务逻辑，更不要直接访问数据库。

常用参数装饰器：

装饰器 取值来源
@Body() 请求体
@Query() URL 查询参数
@Param() 路径参数
@Headers() 请求头
@Req() / @Res() 原生请求/响应对象（尽量少用，用了就脱离框架抽象）

Service：业务逻辑的唯一归属地

@Injectable() 的作用是告诉 Nest：这个类可以被容器管理。没有它，构造函数注入会失效。

模块化与依赖注入

这两块是 Nest 与 Express 最大的分水岭，也是新手最容易绕晕的地方。

Module：组织单元

一个模块声明四件事：依赖了谁（imports）、提供了什么（providers）、暴露了哪些路由（controllers）、对外开放哪些能力（exports）。

⚠️ 最常见的报错 Nest can't resolve dependencies of the XxxService，90% 是因为：Service 没写进 providers，或跨模块使用时对方模块没 exports、当前模块没 imports。

依赖注入：构造函数注入

对比 Express 里到处 import { userService } from '../services/user.service'，注入的价值在于：依赖来自容器而不是文件路径，因此可以随时替换成 mock、替换成另一个实现。

全局模块与动态模块

频繁被注入的基础能力（数据库、配置、日志）不要每个模块都 import，用 @Global() 标记一次：

需要接收参数的模块用动态模块，约定三种命名语义：

方法名 语义
forRoot() 只配置一次，通常配合 isGlobal
forFeature() 注册当前模块用到的资源（如实体）
register() / registerAsync() 每个模块各配一次

自定义 Provider

Provider 的本质是「token → 实例」。除了类，还可以用四种写法：

💡 面向接口编程时用字符串/Symbol token，让 Service 依赖抽象而不是具体类，这也是写单测时替换依赖的关键。

Provider 作用域

作用域 说明 场景
DEFAULT（单例） 全局一个实例 绝大多数情况
REQUEST 每个请求一个实例 需要读取当前用户、请求上下文
TRANSIENT 每次注入都新建 有状态的工具类

⚠️ REQUEST 作用域会「传染」：谁注入了它，谁也会变成 REQUEST 作用域，一路往上直到 Controller，性能开销明显。优先考虑用 nestjs-cls 之类基于 AsyncLocalStorage 的方案传递请求上下文。

DTO 与参数校验

为什么需要运行时校验

TypeScript 的类型编译后不存在。@Body() dto: CreateUserDto 只是编辑器提示，请求体里传什么都能进来。所以需要一个类（编译后仍存在）加上装饰器，在运行时验证。

DTO 有两层价值：运行时校验 + 类型定义 + 自动生成 Swagger 文档。

拦截器与异常过滤器

拦截器处理「正常流程的切面」，异常过滤器处理「错误流程的出口」，两者共同决定接口最终返回什么。

拦截器能做什么

拦截器在控制器方法前后各插一段逻辑，属于 AOP 切面。典型用途：统一响应包装、超时控制、缓存、序列化。

e2e 测试：测整条链路

测试要点

  • 单元测试 mock 依赖，e2e 测试才需要真实数据库
  • e2e 用 app.getHttpServer()，不要真的监听端口
  • 一定要 afterAll(() => app.close())，否则测试进程不退出
  • e2e 建议单独一个测试库，或每个用例包事务回滚
  • ❌ 不要用 useGlobalPipes() 后再在 e2e 里重复注册——两者会叠加

常见问题

问题 原因 解决方案
Nest can't resolve dependencies of Xxx Provider 未注册 / 跨模块未 exports 检查 providers、imports、exports 三处
DTO 校验完全不生效 只写了装饰器，没注册 ValidationPipe 用 APP_PIPE 或 app.useGlobalPipes 注册
Query 参数校验失败（数字变成字符串） HTTP 参数全是字符串 加 @Type(() => Number) 或开启 enableImplicitConversion
多余字段被静默忽略 未开启 whitelist 设置 whitelist: true + forbidNonWhitelisted: true
@Body() 拿到的是 plain object 而非 DTO 实例 未开启 transform ValidationPipe({ transform: true })
Guard 里拿不到 req.user JwtStrategy 未注册或 Guard 顺序不对 确认 JwtStrategy 在 providers 中，Guard 在拦截器之前执行
全局 Guard 把所有接口都拦了 没有白名单机制 加 @Public() + getAllAndOverride
拦截器返回的数据结构被改坏 map 里重复包装或二次 JSON 化 只在 next.handle().pipe(map(...)) 里包装一次
ExceptionFilter 拿不到 request.url 用了 ctx.getResponse() 但没走 HttpAdapterHost 注入 HttpAdapterHost，用 httpAdapter.reply()
启动时报 UnknownDependenciesException 用了 useGlobalFilters(new X()) 导致无法注入 改用 APP_FILTER / APP_GUARD / APP_PIPE / APP_INTERCEPTOR
生产环境表结构被改 synchronize: true 生产设 false，改用 Migration
密码字段被接口返回 实体未隐藏敏感列 @Column({ select: false }) + 响应 DTO 白名单
测试跑完进程不退出 没有关闭应用/连接 e2e 里 afterAll(() => app.close())
Docker 停止时请求被中断 未开启 ShutdownHooks app.enableShutdownHooks()，并调大优雅终止时间
日志里没有 requestId pino 未配置 genReqId 配置 genReqId 并在响应头回吐 ID
热更新时连接数暴涨 Dev 下每次重建实例 数据库客户端实现 OnModuleDestroy，或用单例封装
Swagger 文档字段为空 未加 @ApiProperty 且未开 CLI 插件 开启 @nestjs/swagger 编译插件
循环依赖报错 A 模块依赖 B，B 又依赖 A 尽量抽公共模块；实在需要时用 forwardRef()
