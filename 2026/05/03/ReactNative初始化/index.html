ReactNative初始化

主流初始化方式有两种：官方脚手架（React Native CLI）和 Expo。Expo 是官方推荐方式，CLI 适合需要精确控制版本或深度集成原生模块的场景。

基于 React Native 0.76 / Expo SDK 55，截至 2026 年 5 月。

两种方式对比

对比项 React Native CLI Expo
初始化速度 较慢 快，聚焦 JS 层
环境配置 需手动配置 Android Studio Expo Go 扫码即用
原生模块 直接接入，无限制 Expo SDK 封装，够用
热更新/预览 需手动配置 Expo Go 扫码即用
项目体积 较大 较小
版本控制 可精确指定任意 RN 版本 跟随 Expo SDK 版本
自定义原生代码 支持 受限，需 expo prebuild

开发环境

CLI 和 Expo 本地构建都需要原生开发环境，Expo Go 开发可跳过。

  • Node.js >= 22.11.0（nvm-windows 管理版本）
  • JDK 17（推荐 Microsoft OpenJDK 17：winget install Microsoft.OpenJDK.17）
  • Android Studio + SDK：参考官方指南，安装后配置 ANDROID_HOME 环境变量指向 SDK 目录（默认 %LOCALAPPDATA%\Android\Sdk），并将 platform-tools 加入 Path
  • 设备：真机开启 USB 调试，或用 AVD Manager 创建模拟器

详细步骤参考 Expo 官方环境初始化指南

本地构建

首次运行 npx expo run:android 会触发 prebuild，生成 android/ 原生目录，APK 自动安装到设备。

app.config.ts 与 Gradle 配置的关系：prebuild 时，Expo 会读取 app.config.ts（或 app.json）中的配置，写入到原生工程文件中。例如 android.package → android/app/build.gradle 的 applicationId，android.versionCode → defaultConfig.versionCode，plugins 中声明的权限 → AndroidManifest.xml。手动改 gradle 文件会在下次 prebuild 时被覆盖，所以原生配置应尽量在 app.config.ts 里通过插件或 extra 字段管理，而不是直接改生成的文件。

npx expo prebuild --clean 会先删除 android/ 目录再重新生成，所有手动修改都会丢失。

Release 构建需要签名配置，首次会报错提示缺少签名文件，按提示用 keytool 生成后重试 npx expo run:android --variant release。

如果接了需要本地编译的原生模块，需先 npx expo install expo-dev-client。

Gradle 编译慢，EAS 提供远程缓存，配置方式参考官方文档。

版本号管理

CLI：在 android/app/build.gradle 的 defaultConfig 中设置：

  • versionCode：整数，每次发布递增，Google Play 用于判断是否为新版本
  • versionName：展示用字符串，如 1.0.0

Expo：在 app.config.ts 中设置 version（对应 versionName）和 android.versionCode，prebuild 时写入 gradle。eas.json 中 autoIncrement: true 可让 EAS 每次构建自动递增 versionCode，不用手动改。

多环境配置

CLI：用 Gradle productFlavors 区分环境（如 dev、staging、production），或用 react-native-config 库管理环境变量。

Expo：通过 eas.json 的 profile 区分环境，app.config.ts 中用 extra 字段传递环境变量，运行时通过 Constants.expoConfig?.extra 读取。构建时 EAS_BUILD_PROFILE 环境变量自动注入当前 profile 名，可在 app.config.ts 中动态读取以切换配置：

.env 文件支持

React Native 默认不读 .env 文件，process.env 只能访问构建时已存在的系统环境变量。

文件后缀约定

前端社区（Vite/CRA）有一套 .env 后缀约定，但 RN 生态不会自动按后缀加载，需要工具配置：

文件 用途 是否提交 git
.env 所有环境共享的默认值 ✅
.env.local 本地覆盖，优先级最高 ❌
.env.development 开发环境专用 ✅
.env.production 生产环境专用 ✅

Debug 与 Release 共存

手机上已装 Release 版本时，USB 调试的 Debug 版本会因包名冲突覆盖安装。解决方法是给 Debug 构建加 applicationIdSuffix：

CLI：在 android/app/build.gradle 的 buildTypes.debug 中加 applicationIdSuffix ".debug"：

Debug 版包名变为 com.example.myapp.debug，与 Release 版互不干扰。

Expo：prebuild 生成的 gradle 默认已包含 applicationIdSuffix ".debug"，所以 Debug 和 Release 版本本身就不冲突。如果发现没有，写一个简单的 Config Plugin 在 prebuild 时注入上述 gradle 配置。

加了 applicationIdSuffix 后，Debug 和 Release 的数据（SharedPreferences、数据库）是隔离的，互不影响。如果需要单独打一个 Debug APK 出来安装，CLI 用 ./gradlew assembleDebug，Expo 用 npx expo run:android（默认就是 Debug）。

常见问题

Q：初始化报 jest-haste-map 或 watchman 错误？

A：Windows 用户可忽略 watchman 相关警告，建议用 WSL2 开发。

Q：Android 模拟器启动不了？

A：检查 ANDROID_HOME 是否指向正确目录（默认 %LOCALAPPDATA%\Android\Sdk）。

Q：高版本 JDK 导致构建失败？

A：React Native 推荐 JDK 17。不兼容的话，改 android/gradle/wrapper/gradle-wrapper.properties 里的 distributionUrl 升 Gradle 版本，或者降 JDK。

Q：Expo 项目想获得原生能力怎么办？

A：执行 npx expo prebuild 生成原生工程，代码不用动，但原生配置要手动维护。
