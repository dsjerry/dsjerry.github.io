files：asar 内文件

文件匹配

files的作用是控制哪些文件会被打进app.asar中。所有的文件路径对应的是根目录（package.json所处的目录）

📦 工具自带了一些默认内置规则，可以不用重复写：

  1. 默认包含**/*（全部文件）
  2. 自动过滤开发依赖（devDependencies）
  3. 自动排除：源码map、测试目录、git配置、IDE文件夹、lock文件、.d.ts文件

注意

如果自定义了任意一条**files包含规则**（不带有!），默认**/*规则将失效，需要手动指定需要打包的目标

📑 规则的执行顺序是数组从上到下：所以应该先包含、后排除；后写的!优先级更高：

如果要排除一个文件夹，单纯使用!folder/**/*只会排除文件夹里面的文件，导致这个空文件夹还是存在的，所以需要使用宏${/*}：

更多匹配语法：

符号 作用
* 单层目录匹配任意字符
** 递归匹配所有子目录
!xxx 排除匹配到的路径
{a,b,c} 多路径简写
`!(a b)`

两种配置写法

  1. 简单的包含和排除
  1. 对象FileSet，这种写法适合静态资源、二进制文件、需要修改打包内路径的场景
  • from：本地源文件夹
  • to：asar 内部存放路径
  • filter：过滤规则

extraResources：asar 外部资源

files 打进的是 app.asar 内部，但有些文件不能放在 asar 里：

  • 可执行文件 / 动态库（.exe、.dll、.so、.dylib）
  • 子进程调用的二进制（ffmpeg、sqlite3 等）
  • 需要被外部程序访问的文件

这些文件需要用 extraResources 放到 asar 外部的 resources/ 目录。

asar 内 vs asar 外

配置 位置 特点
files app.asar 内部 打包进 asar，不可直接执行
extraResources resources/ 目录（asar 外） 保留原始目录结构，可执行
extraFiles 安装根目录（asar 外） 放到更上层

代码签名

代码签名是对构建之后的产物进行数字签名，证明软件来源可信且未被篡改。

为什么需要代码签名

场景 未签名的后果
Windows SmartScreen 弹出”Windows 已保护你的电脑”警告，用户无法直接打开
macOS Gatekeeper 提示”无法打开，因为无法验证开发者”
自动更新 macOS 强制要求签名，否则无法使用 electron-updater
企业部署 部分企业安全策略只允许安装已签名软件

签名证书获取

Windows（代码签名证书）

方式一：购买商业证书（推荐）

向证书颁发机构（CA）购买：

  • DigiCert
  • Sectigo
  • GlobalSign
  • Cost：约 $200-500/年

方式二：自签名证书（仅开发/测试）

使用 PowerShell 生成自签名证书，仅适合本地测试，无法通过 Windows SmartScreen 验证，不适合对外分发。

macOS（Apple Developer 证书）

必须使用 Apple Developer 证书（自签名无法通过 Gatekeeper）。

  1. 注册 Apple Developer Program（$99/年）
  2. 在 Apple Developer 后台生成证书
    • Development：开发测试用
    • Distribution：发布用（必须使用此证书签名才能通过 Gatekeeper）

开发测试可临时用 Keychain Access 生成自签名（仅本地有效），但无法用于分发。

签名验证

平台 验证命令
Windows signtool verify /pa "path/to/app.exe"
macOS codesign --verify --deep --strict "path/to/app.app"

查看签名详情：

  • Windows：signtool verify /v /pa "app.exe"
  • macOS：codesign -dvv "app.app"

最佳实践

  1. 证书安全：使用 CI/CD 平台的 Secrets 功能，不要硬编码
  2. 签名时机：在最终构建流程中签名，不要在开发环境签名
  3. 测试验证：发布前在干净系统上测试安装流程
  4. 证书续期：提前设置证书续期提醒
