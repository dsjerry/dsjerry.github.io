uni-app应用更新

WGT 增量更新 + APK 全量更新，离线 SDK 打包场景。

更新策略

当前操作过程在 CLI 版本下进行。更新还会受到 HBuilder 版本、离线SDK版本的影响，查看版本关系

文章中涉及到的版本情况如下：

组件 版本
HBuilderX 5.07.2026041006
uni-app CLI（@dcloudio 包） 3.0.0-5000720260410001（对应 HBuilderX 5.07）
离线 SDK（HBuilder-Integrate-AS） 对应 HBuilderX 5.07（uniapp-v8-release.aar 等 SDK 库）
Gradle 8.13（wrapper）
Android compileSdk 35
Android targetSdk 33
Android minSdk 21

HBuilderX 5.07、uni-app CLI 3.0.0-5000720260410001、离线 SDK 三者版本是对应的，升级任何一个都必须同步升级另外两个。

更新方式

WGT 增量 APK 全量
适用场景 只改前端（页面/JS/样式） 改原生层（SDK/插件/AndroidManifest）
打包方式 HBuilderX → 发行 → 制作移动App资源升级包 Android Studio 打 release APK
安装方式 plus.runtime.install() plus.runtime.openFile()
文件大小 小 apk完整大小

版本号体系

两套版本号独立管理：

版本 说明 变更场景
versionCode 原生 APK 版本（build.gradle） SDK / 原生插件 / AndroidManifest 变更
wgtVersion 前端资源版本（本地 storage） 页面 / JS / 样式迭代

更新判断：

  • 服务端 versionCode > 本地 versionCode → APK 全量
  • 服务端 versionCode == 本地 && 服务端 wgtVersion > 本地 wgtVersion → WGT 增量
  • 否则 → 无更新

调试方式

测试更新可以直接使用 HBuilderX 真机运行、模拟器运行，日志输出使用 console.log。

但是要看到底层的日志输出、崩溃原因，需要用到 Android Studio 中的 LogCat（界面的左下角）查看错误日志。

测试更新是否正常，可以有以下步骤：

  1. 连续测两个 wgt 包，看是否增量成功，检查是否有内容缺失特别是renderjs渲染的内容是否正常
  2. 测试全量包的安装过程是否顺利
  3. 用户取消更新后，再次检查更新是否还能正常弹出

前端实现

安卓端可以参考HTML5+ 规范

关键点

  1. plus.runtime.install 必须 { force: true } — 跳过版本校验。否则某些设备（如小米）上 plus.runtime.versionCode 会变成基座版本号导致安装失败（uni-app bug）
  2. 安装成功必须 plus.runtime.restart() — 否则新内容不生效
  3. 避免 uni.showLoading — dcloud_circle_white_progress drawable 有可能触发崩溃（模拟器 pixl 8）
  4. 下载路径用 _doc/update/temp.wgt — 不需要 convertLocalFileSystemURL，SDK 自动解析
  5. APK 安装用 plus.runtime.openFile() — plus.runtime.install() 对 APK 支持有限，某些版本不弹安装界面

版本号管理

versionName 对齐：build.gradle 和 manifest.json 的 versionName 必须一致，否则即使 force: true 也可能安装失败。

发版版本管理：

场景 改 manifest.json 改 build.gradle 改后端 wgtVersion
只改前端（页面/JS/样式） versionName+1, versionCode+1 ❌ 不动 同步 manifest.json 的 versionName
改了原生层（SDK/插件/AndroidManifest） versionName+1, versionCode+1 versionName 和 manifest.json 保持一致 同步 manifest.json 的 versionName
不改代码只重新发版 不变 不变 改高即可

发版流程：

  1. 改前端代码 → HBuilderX → 发行 → 制作移动App资源升级包 → 生成 .wgt
  2. 上传 WGT 到服务器 / OSS / MinIO
  3. 升级服务端 wgtVersion（比当前版本高）
  4. 重启后端服务
  5. 用户打开 App 自动检测 → 弹窗 → 下载 → force:true 安装 → restart 生效

如果改了原生层（SDK/插件/AndroidManifest/build.gradle），必须重新打 APK 全量包，不能只发 WGT。

常见问题

缺 zip4j 依赖

表现：plus.runtime.install() 安装 WGT 时报 java.lang.NullPointerException: Attempt to read from null array

根因：uni-app 离线 SDK 漏引了 zip4j 库。WGT 本质是 zip 压缩包，plus.runtime.install() 解压时需要 zip4j 来处理，没有就崩。

解决：build.gradle 的 dependencies 里加上：

force: false 版本校验

表现：WGT installation package manifest.json the version of the file does not match

根因：plus.runtime.install() 默认会对比 WGT 包内的 versionCode 和当前 App 的 versionCode。但在某些设备（如小米）上，plus.runtime.versionCode 返回的是基座版本号而非 App 版本号，导致永远校验不通过。这是 uni-app 的 bug。

解决：传 { force: true } 跳过版本校验：

安装后没重启

表现：WGT 安装成功，但 App 内容没变，还是旧版本

根因：WGT 安装只是把新资源文件写到了 App 的 www/ 目录，但当前运行中的页面还是内存里的旧资源，必须重启才能加载新文件。

解决：安装成功回调里调用 plus.runtime.restart()：

uni.showLoading 在 Android 15 崩溃

表现：调用 uni.showLoading() 时 App 闪退，logcat 报 drawable 资源找不到

根因：uni.showLoading 内部引用了一个叫 dcloud_circle_white_progress 的 drawable 资源，这个资源在 Android 15+ 的 theme 处理中异常，导致 inflate 失败。

解决：避免使用 uni.showLoading，改用 console.log 或自定义 UI：

FileProvider 不存在

表现：App 启动直接崩溃，logcat 报 ClassNotFoundException: io.dcloud.common.util.FileProvider

根因：DCloud 官方文档建议在 AndroidManifest.xml 中配置 DCloud_FileProvider 用于 Android 7+ 的文件 URI 共享。但这个类在离线 SDK 的 AAR 包中不存在，编译能过（因为 manifest 合并不检查 class），运行时一加载就崩。

解决：不要手动配 FileProvider。APK 安装改用 plus.runtime.openFile()，它内部自己处理了 URI 转换：

localhost 在真机上连不上

表现：真机测试时版本检测接口请求失败

根因：localhost / 127.0.0.1 指向的是手机自己，不是电脑。开发时电脑上跑的后端服务，手机通过 USB/WiFi 连接，IP 地址是电脑的局域网 IP。

解决：用电脑的局域网 IP 替换 localhost：

查看电脑 IP：ipconfig（Windows）或 ifconfig（Mac/Linux），找 IPv4 地址。

WGT 和 APK versionName 不一致

表现：WGT 安装失败，即使加了 force: true 也可能失败

根因：build.gradle 的 versionName 和 manifest.json 的 versionName 必须一致。不一致时，plus.runtime.install() 在解压后对比版本号发现不匹配，某些系统版本会拒绝安装。

解决：两个文件保持同步：

服务端 wgtVersion 不升级

表现：App 发版后用户收不到更新

根因：前端代码改了、WGT 包上传了，但后端接口返回的 wgtVersion 还是旧版本号，前端对比后发现没有更新，直接跳过。

解决：每次发版后记得改高后端 wgtVersion。可以在数据库或 JSON 配置中更新，确保比当前 App 本地 storage 里的 wgtVersion 大。

HBuilderX 和离线 SDK 版本不匹配

表现：WGT 安装后崩溃，或 App 启动弹版本警告

根因：HBuilderX 编译 WGT 时用的是它自带的编译器版本。离线打包 SDK 也有自己的版本。如果两者不一致，编译出的 www/ 资源格式和 SDK 运行时预期的不匹配，轻则弹版本警告，重则直接崩溃。

解决：打包 WGT 的 HBuilderX 版本必须和离线 SDK 版本完全一致。升级 HBuilderX 后必须同步下载对应版本的离线 SDK，重新生成 www/ 资源。

Android 10+ 文件路径受限

表现：WGT 或 APK 下载失败，或下载后安装时报文件找不到

根因：Android 10 (API 29) 开始引入了分区存储（Scoped Storage），App 不能随意访问外部存储路径。如果用 plus.downloader.createDownload() 时指定了外部路径（如 /sdcard/），可能因权限不足导致下载失败。

解决：使用 _doc/ 前缀路径，SDK 会自动映射到 App 的内部存储目录，不受分区存储限制：

不需要手动调用 convertLocalFileSystemURL()，SDK 会自动解析 _doc/ 路径。
