UTS插件使用

离线SDK打包：uni_modules -> uts -> kotlin

背景

uniapp 项目中如果要使用一些原生的功能可以使用UTS插件，在离线SDK打包的时候需要将插件集成到 Android 项目中

UTS插件

插件本身为 uts 源码，但是离线打包的时候需要编译为对应的原生代码（比如安卓的 Kotlin）。Hbuilder 打包安装包资源的时候会自动完成这个编译操作

文件 用途
src/uni_modules/<plugin>/utssdk/app-android/index.uts UTS 源码（HBuilderX 编辑用）
unpackage/resources/uni_modules/<plugin>/utssdk/app-android/src/index.kt ← 离线打包用这个

注意

对于离线SDK来说 UTS 的版本变更会影响到原生依赖内容，涉及到的依赖也要跟随变更，比如：

  • Android studio 2025.1.2 以上
  • gradle 版本 8.14.3
  • org.jetbrains.kotlin.android 版本 2.2.0
  • com.android.application / com.android.library 版本 8.11.1
  • 重要：uts-kotlin-gradle-plugin-0.0.1.jar/uts-kotlin-compiler-plugin-0.0.1.jar 有升级，需要手动更新

AAR

utsplugin-release.aar 必须与 uniapp-v8-release.aar 来自同一个 SDK 版本。两者版本不一致会导致运行时崩溃，且 Gradle Sync 和编译都能通过，只有运行时才会暴露。

排查方法：对比两个文件的大小（字节数），如果与 SDK 目录中的不一致说明版本混了。最稳妥的做法是从同一个 SDK 版本目录下复制所有 aar 到 app/libs/。

以 sup-gpslocation 插件为示例

Android

在 HBuilder 中发行 -> 本地打包 -> 生成本地打包App资源后，uts 插件会在unpackage/resource/app-android/uni_modules目录下。这里包含源码（比如安卓的 Kotlin 代码index.kt）

前置依赖检查

配置 UTS 插件前，确认 Android 项目已有以下基础设施：

检查项 文件 内容
Kotlin classpath 根 build.gradle classpath 'org.jetbrains.kotlin:kotlin-gradle-plugin:2.2.10'
UTS 桥接库 app/libs/ utsplugin-release.aar
UTS 依赖 app/build.gradle okhttp、core-ktx、kotlin-stdlib、kotlin-reflect、kotlinx-coroutines、XXPermissions
jitpack 仓库 根 build.gradle maven { url 'https://jitpack.io' }
Kotlin 插件 app/build.gradle apply plugin: 'kotlin-android'

常见问题

Kotlin 插件选错导致编译失败

表现：gradle.properties 有 android.builtInKotlin=false，模块用 com.android.built-in-kotlin 插件后 Gradle Sync 失败。

根因：com.android.built-in-kotlin 是 HBuilderX 内置 Kotlin 编译器插件，与离线打包场景冲突。

解决：改用 org.jetbrains.kotlin.android，根 build.gradle 需有 kotlin-gradle-plugin classpath。

Service 类名与包名不匹配

表现：前台服务启动失败，startForegroundService 抛异常。

根因：UTS 源码中 setClassName() 引用了 uniGpslocation，但编译后的 Kotlin 包名是 supGpslocation。AndroidManifest 中的 android:name 也写错了。

解决：三处必须一致 — Kotlin package 声明、AndroidManifest android:name、代码中 setClassName() 引用。

compileOnly vs implementation

表现：类重复冲突 DuplicateClassException。

根因：插件模块用 implementation 引入 SDK 依赖，运行时与 app 模块的同类冲突。

解决：插件模块所有 SDK 依赖必须用 compileOnly，运行时由 app 模块统一提供。

Git Bash 下 gradlew clean 报错

表现：./gradlew clean 报 ClassNotFoundException: org.gradle.wrapper.GradleWrapperMain。

解决：手动清理 rm -rf android/build/ android/app/build/ android/<plugin>/build/。

模块残留多余文件

表现：模块目录有 src/androidTest/、src/test/、consumer-rules.keep、keepRules/ 等。

根因：Android Studio 创建 library module 时自动生成的模板文件。

解决：UTS 插件不需要这些，直接删除。最终模块只保留 .gitignore、build.gradle、AndroidManifest.xml、index.kt。
